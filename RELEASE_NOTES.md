# Release notes

## Unreleased

- Amino-acid annotation of the designed changes (`src/protein.js`, `docs/design-handoff.md`). A design names the codons of its changes: a design report has `p.L177L: CTG -> CTA` for each silent change, a design file has marker labels such as `p.L173L` with `CTG>CTC` and the design label `R176C (CGC>TGC)`. From those the strand and reading frame of the control read are found, and every designed change gets its amino-acid change, the intended edit too. Figures: the markers read `R176C CGC>TGC` and `L177L silent CTG>CTA` instead of `intended change C>T`; a protein row translates the control in the design's reading frame, with the designed codons coloured and numbered; a box under each clone gives its residue at the designed codons (a second base of at least 20 % shows as `R/C`, dashed) and at up to three codons that changed without being designed (red). The selection figure's table headers and the report's per-position table carry the same labels. `results.json` markers gain a `protein` object.
- Nothing is added when the design names no codons, when no frame fits them equally well, for bases labelled noncoding, or for bases past the first in-frame stop codon. No estimate, call or decision uses the annotation; the estimation files are unchanged.
- Limits: the frame comes from the design's own notes, not from a gene record, and the protein row translates the genomic read, so an intron inside the stretch would be translated as well.

## 0.5.2 (2026-10-13)

- PDF export: every figure can be saved as a vector PDF (browser: a (PDF) button next to (SVG) and (PNG) for the clone selection, base-call alignment, aligned chromatograms, summary graph, protein products, the aligned chromatogram and the figure of the selected sample; command line: `run` writes a `.pdf` next to each `.svg`, `--no-pdf` turns that off, and `figure --out figure.pdf` works). The PDF is drawn from the SVG by a new dependency-free converter, `src/svgPdf.js`; text uses the standard Helvetica and Courier faces (not embedded). See `docs/pdf-export.md`.
- No estimate, interval, call, decision or figure layout changes. The engine files are byte-identical to 0.5.1 apart from `saveFigure.js` (the PDF button helper) and the version string in `report.js`; `bench/ENGINE_FREEZE_0.5.2.json` records them.
- Tests: `test/svg-pdf.test.js` (17 tests) converts every figure of the app and checks the page size, one text operator per drawn text, the cross-reference table, that nothing is skipped or lost, and the compressed content against the plain content.

## 0.5.1 (2026-10-13)

- HDR score mode (SNP, small tag): the intended-edit share is named the HDR score (ICE's HDR or KI score) in the summary graph, plate view, clone selection figure (the score and its interval are written out), report tables and headline, aligned-chromatogram labels and the browser; `support_basis` reads "HDR score (intended edit), lower bound of the 95% interval". Clones are still ranked by the lower bound of the interval. Blocking changes without the edit stay separate and are not counted. No estimate, interval, call or decision changes.
- Fix: the command line named no clone to carry forward for a knockout run (`run` without `--panel`: "0 of 8 clones to carry forward first"). The unset `--panel` reached the ranking as an undefined option and replaced the default of three; the browser, which passes no option, was not affected. An undefined or null option no longer replaces a default (`src/recommend.js`); a test covers the default panel of a knockout plate.
- KO score mode (no gene record): the number in the support column is now named "KO score" everywhere (summary graph and its footnote, plate view, clone selection figure, browser, `support_basis` in recommendation.csv), defined as in ICE (frameshift or an indel of 21 bp or more), and no longer described as a prediction of protein loss. With a gene record the wording is unchanged ("Knockout support").
- Ranking in KO score mode: ties on the score are broken by the lower bound of the KO-score interval after the existing keys, and up to two clones with the same genotype count towards the panel (a second clone with one deletion is a replicate; before, one clone per genotype put a compound heterozygote with a noisy trace third). With a gene record, one clone per genotype as before. Edit workflows and every estimate, interval, call and decision are unchanged.
## 0.5.0 (2026-10-13)

- Clones aligned with the wild-type control (`src/alignedView.js`, `src/alignedFigure.js`, `docs/aligned-chromatograms.md`). The HTML report gets, for every clone, an annotated chromatogram aligned with the control (guides with PAM and cut, designed changes, base calls of both reads, every base that differs from the control, a second base where one is at least 20% of the signal, a block for the bases a clone lacks), and a new section "All clones aligned": the base calls of all clones as an alignment on the control (best clone first), and the chromatograms of all clones stacked on the same stretch (up to 48 clones). The same figures are in the browser (sample view and a section under the summary graph, SVG and PNG downloads) and from the command line (`clones_alignment.svg`, `clones_aligned.svg`, and with `--clone-figures` one SVG per clone in `chromatograms/`).
- Design report with several donors (`src/manualSpec.js`, `src/quick.js`, `docs/clone-selection.md`): for a point edit, all donors recommended in an exported design report are used together (markers merged; the change every donor carries is the intended edit; each donor lists the markers it carries). Before, only the first was read, so a clone made from another donor was read as a partial conversion. On a real 24-clone SNP plate designed with two ssODNs, the browser path (design report) gave 3 decisions different from the design-file path, and two clean homozygous clones made from the second donor were rejected; with this change the design report and the design file give identical results (every estimate, interval, decision and rank). `--donor SEQ1,SEQ2` takes several donors on the command line.
- Clone selection figure (`src/selectionFigure.js`): the clones to carry forward as chromatograms aligned with the control under the guides, cuts and designed changes, and a table of all clones (share of the donor base at each designed change, genotype, call, support). In the report (section "Clone selection", with suggested next steps), in the browser (SVG and PNG) and as `clone_selection.svg`.
- The default number of clones to carry forward is three for a knockout and six for a wanted edit (replicates of one genotype); `--panel N` and a box in the browser set it. The ranking itself does not change.
- The view is kept on each analysed sample as `view` (plain data, about 9 KB), built by `analyseSample` and left out of `results.json`; `options.traceView = false` switches it off. The view itself never changes an estimate, interval, call or decision.
- Report size: about 65 KB per clone; above 48 samples the per-sample figure is kept for samples that were not rejected, and the stacked chromatograms are left out.
- `QC_VERSION` and `package.json` read 0.5.0. Built on 0.4.2 (pull request 6). Of the 41 files hashed in `bench/ENGINE_FREEZE_0.4.2.json`, 39 are byte-identical; `batch.js` and `report.js` changed, and `alignedView.js` and `alignedFigure.js` are added (43 hashed in `bench/ENGINE_FREEZE_0.5.0.json`). For a design file, or a design report with one donor, every estimate, interval, call and decision of 0.4.2 is unchanged: on a real 24-clone SNP plate run with the same `--panel`, `results.csv`, `recommendation.csv`, `resequence.csv`, `summary.svg` and `plate.html` are byte-identical to 0.4.2 (the run time of each sample aside).

## 0.4.2 (2026-10-13)

- Clone recommendation for a wanted edit (SNP, small tag, knock-in; `src/recommend.js`, `docs/recommendation.md`): clones with the same genotype are now replicates and each counts for the panel, ranked by the lower bound of the intended-edit interval (a plate of six clean homozygous clones names up to `--panel N` of them). Before, the best clone of each genotype formed the panel and the others were listed as backups, which suits knockouts (one predicted outcome) but not an edit.
- New priority `not_recommended`: the sequence does not support the wanted edit (support tier unsupported). Such clones get no rank and are not in the panel; before they could fill the reserve. Action texts for an edit say "carrying the wanted edit".
- Knockout and deletion workflows rank as in 0.4.1 apart from that new class; the recommendation table for the 8 clones of a real knockout plate is identical to 0.4.1.
- Reporting only: no estimate, interval, call or decision changes. Of the 41 files hashed in `bench/ENGINE_FREEZE_0.4.1.json`, 38 are byte-identical; `recommend.js`, `summaryFigure.js` and `report.js` (the version string) differ, and `bench/ENGINE_FREEZE_0.4.2.json` records the new hashes. On the 24 clones of a real SNP plate the 32 estimation and decision columns of `results.csv` are identical to 0.4.1. The summary graph and the browser plan column read "not recommended" (`src/summaryFigure.js`, `src/QuickStart.jsx`).
- `QC_VERSION` and `package.json` read 0.4.2.

## 0.4.0 (2026-10-12)

- Clone recommendation (`src/recommend.js`, `docs/recommendation.md`): the clones of a run are ranked by the knockout support (how strongly the allele-level prediction says that no functional protein is left; weights are ordinal and provisional) and the best clone of each genotype forms the panel to carry forward first. Browser: a Priority column, the support and reasons for the selected clone, a recommendation download. Command line: `run` writes `recommendation.csv` and prints the panel; `recommend results.json` ranks a finished run; `--panel N`. `results.csv` gains `knockout_support`, `priority_rank` and `recommendation` as trailing columns; the plate view gains an ordered table.
- Predicted protein products figure (`src/proteinFigure.js`, `docs/functional-knockout.md`): for each sample with a gene record, the products of its alleles drawn on the protein (residues kept, frameshifted tail, NMD, mass), with the stretches where an antibody epitope sees every product or the full-length protein only; under the allele table in the browser (SVG and PNG), in the HTML report, and as `protein_products.svg` for the whole run. For this the functional assessment now also reports, for each splice outcome, its details and the residues kept by exon skipping (`details.splice.*.details`, `details.splice.skipping.details.keptAa`) and the exon lengths, marked regions and epitope of the context; no call, score or decision changes.
- Protein results (`--observations protein.csv`, the file `calibrate` reads): absent protein accepts a clone whose sequence shows a clean knockout, present protein rejects it, truncated or reduced protein holds it. The earlier decision is kept in `decision.before` and the reasons name the result.
- No estimation file changed: 33 of the 37 files hashed in `bench/ENGINE_FREEZE_0.3.1.json` are byte-identical; of the four that differ, `report.js`, `plateReport.js` and `calibration.js` are reporting code and `coding.js` only reports more of what it already computes (see above). Without a gene record `coding.js` is not used. `bench/ENGINE_FREEZE_0.4.0.json`.
- `QC_VERSION` and `package.json` read 0.4.0.

## 0.3.1 (2026-10-12)

- Functional knockout assessment: a GenBank record that also carries a neighbouring gene (common for genomic records) no longer lets that gene's coding sequence be taken as the protein. Only the coding sequences of the gene the design's reference window lies in are modelled; the others are listed in a warning (`src/coding.js`). Before, the longest CDS of the record was the primary protein, so a neighbour with a longer CDS would have been assessed instead. A record whose window lies in no gene is unchanged. Designs that carry the coding block of the design file were not affected (the block holds one gene). Estimates, intervals and decisions without a gene record are unchanged.
- The warning for a partial CDS in the record now names the gene instead of an index.
- `QC_VERSION` and `package.json` read 0.3.1.

## 0.3.0 (2026-10-12)

- Engine: the read offset is re-anchored in the 20 bases before the cut when the two reads' base calls have drifted apart since the upstream alignment stretch (`src/offset.js`, option `refineOffset`). Fixes sizes that were one base out on a control read with extra base calls; never changes a pair whose offset already fits.
- Engine: unplanned base changes (a second base the design does not predict) are named with position and base (`src/unplanned.js`, option `unplanned`); results carry `unplanned`, a warning and a CSV column; an otherwise accepted clone is held (`holdOnUnplanned: false` to turn off).
- UI: the classic form's design box now takes an HTML design report (.html, .htm) as well as a .json design file (guides and recommended donor fill the form; before, only .json could be chosen). The Quick Start page already accepted reports.
- Bench: `bench/adapters_sangerdecon.py` (comparator adapter, separate from the frozen adapters) and `bench/PREREGISTRATION_0.3.0.md`.
- Evidence and limits: `docs/changes-0.3.0.md`. On 350 simulated traces (a fresh seed) the output is identical to 0.2.0.
- Functional knockout assessment (`src/coding.js`, `src/genbank.js`): with a GenBank gene record, each allele is placed in the coding sequence and translated; premature stops are judged by the exon-junction rules for nonsense-mediated decay, truncations by the share of protein kept and essential regions lost, early stops by downstream in-frame ATGs, splice-site edits as exon skipping versus intron retention, plus start loss, stop loss and in-frame changes. A clone call (predicted knockout, with caveats, not a knockout, uncertain), a functional knockout score with interval and a list of confirming experiments (Western blot, RT-qPCR, RT-PCR) are added to the table, report, CSV and decision layer. A knockout is accepted only when the call is a predicted knockout without caveats. The prediction is not calibrated on protein measurements (`docs/functional-knockout.md`).
- Design file: a design written by the design app for a knockout or deletion carries a `coding` block (gene region and coding exons); the functional assessment then runs without a second GenBank upload (`docs/design-handoff.md`). A gene record given with the traces takes precedence.
- Pre-cut discordance warning: for knockout and deletion designs it now looks at the 40 bases next to the cut instead of the whole alignment window, so a base-calling shift early in the read no longer warns; designs that read donor markers keep the whole window. Warnings on 160 laboratory clones fall from 46 to 29, estimates are unchanged; the warning did not predict knockout error before or after, and flagged all 3 SNP overcalls (one locus) under both rules (`docs/discordance-warning.md`).
- Calibration of the functional call: `node cli/assured-qc.mjs calibrate results.json observations.csv` scores the calls against protein (and RNA) results with Wilson intervals, by call and by allele class (`src/calibration.js`, `docs/calibration.md`, template `docs/calibration-template.csv`). No protein data have been used yet; thresholds are unchanged.
- Marker-level response: investigated on 45 real SNP clones and not added (`docs/marker-response-notes.md`); the effect appears at one locus and the allele fit already absorbs it. Real-data guard unchanged (knockout readout MAE 2.88, 3 SNP overcalls).
- Final freeze: `bench/ENGINE_FREEZE_0.3.0_final.json` (engine file hashes, scorer hash, test count). On a fresh seed (20261220, 351 simulated traces) the engine merged on 2026-10-12 and the engine frozen on 2026-10-09 give identical output for every trace (edited share, intended edit, knockout score, genotype), so the scorecard is the same for both (`docs/changes-0.3.0.md`). `QC_VERSION` is now 0.3.0 (it read 0.1.0).
- The earlier knockout score is relabelled the frameshift score (proxy) and is unchanged; without a gene record nothing else changes.
- Command line: `--genbank`, `--transcript`, `--regions`, `--epitope`; the gene record file name and SHA-256 are written to `run.json`. Start page: optional GenBank file with essential regions and antibody epitope.
- Tests: 29 added (record parser, strand handling, window location, independent translation check, NMD rules, splice sites, start loss, isoforms, decision, report, command line, design-file coding block, calibration, discordance warning).

## 0.2.0 (preview)

- Engine: unknown-base insertions to 10 bp; adaptive search for large deletions (31-250 bp, either cut or spanning), donor edit carrying an indel as its own allele; gated unpenalised refit and background baseline (only when the fit is good); joint fit of forward and reverse reads with a per-read agreement flag.
- Every result has profile-likelihood intervals (edited, wild type, intended edit, knockout score), a "could hide up to" bound, and a confidence tier derived from the interval width. The old any-warning flag did not predict errors (AUC 0.5); interval width does (AUC 0.8-0.9 on the development set).
- Decision layer: accept, hold, re-sequence or reject, with reasons; plate report (8x12) and re-sequence list. A held-out run found that an in-frame 18-base deletion between the cuts was accepted as a knockout; fixed and tested.
- Sample sheet and automatic pairing (167 of 172 real files correct, the 5 errors flagged low confidence), design-report import, zero-configuration start page with a worker pool, publication figure (SVG, PNG at 300 dpi).
- Command line (`cli/assured-qc.mjs`) with worker threads, run provenance (input SHA-256, parameters).
- Other nucleases (SpCas9, NG, SaCas9, Cas12a, SpRY), cut-site discovery from traces and a base-editing workflow (per-position conversion): checked on simulated traces only.
- Benchmark harness (`bench/`): simulator from real control peaks, adapters for ICE, peaksplit and Assured_TraceEdit, a scorer frozen before use, the known-mixture wet-lab protocol (not run). Held-out results in `docs/results.md`, including the criteria that were not met.
- 107 engine tests. The browser interface could not be built or viewed in the development environment (the bundler cannot run there); the production build and the tests pass in CI (Node 20), but nobody has looked at the interface in a browser yet.

## 0.1.0 (preview)

- Five workflows: knockout, deletion between cuts, SNP correction, small tag knock-in, large tag or reporter knock-in (junction reads and out-out band sizes).
- Design hand-off file (`assured-qc-design/1`) from the design app, or manual entry of guides and donor.
- Allele deconvolution with separate reporting of intended edit and blocking-changes-only conversion; clone genotype calls.
- HTML report and CSV table downloads; analysis runs in a web worker, files never leave the browser.
- Synthetic validation set and comparison against Synthego ICE 1.2.0 (`docs/validation.md`).
- Warning when the control and edited traces already differ before the cut (threshold 0.25, provisional); refusal of swapped, truncated and mismatched pairs. 68 engine tests.
- A control whose own signal is mixed (for example after a homopolymer run) is reported as such, with the position where the mixing starts and the run in the design, instead of as the wrong design (`src/diagnose.js`). Found on real reads from a project locus, where an (A)20 run upstream of the start codon turned every read mixed.
- Run on 172 laboratory control/edited pairs (12 sets, 160 clones, 12 pools) against ICE 1.2.0 and against direct chromatogram readouts (`docs/validation.md`, the clone-level table (not published)). Two failures found and fixed: a read with a poorly called start was refused although most of it aligned, and a complex pool was reported as 4% edited because the unexplained signal was renormalised away (new `unexplained` column in the table, report and CSV). 72 engine tests.
- A trace start that differs from the control by fewer than 10 bases is no longer listed as a warning (it was present in most pairs). `scripts/run_batch.mjs` runs a batch from the command line with the same engine and report as the web app.
- Known limits: three-guide multiplex headline differs from ICE on the one example tested; no sequencing-confirmed genotypes yet; poor traces remain the main source of error; at most two alleles per clone.
